# GSC-20261023: search indexing for status.skyhong.tw and n8n.skyhong.tw

Owner split: this repository's code, tests, and deployment were handled here; Search Console
properties, sitemap submission, and Google-side inspection belong to the Codex thread. Submitting
or reading a sitemap is not evidence that anything is indexed.

## status.skyhong.tw

**Defect.** The public dashboard (indexed, HTTP 200, with a description) had no canonical link,
`/robots.txt` and `/sitemap.xml` returned 404, and its JSON API, `/metrics`, health, feed, and
badge responses carried no indexing directive, even though the footer links `/metrics`,
`/feed.xml`, and `/badge.svg`.

**Fix.** Commit `7ccf711` ("Serve a canonical, robots.txt, and sitemap for the public dashboard
only"), see `seo.mjs` and README *Search indexing*:

- `<link rel="canonical" href="https://status.skyhong.tw/">`, rewritten from `PUBLIC_ORIGIN`
  (unset in production, so the default origin applies).
- `/robots.txt`: `Allow: /` plus `Sitemap: https://status.skyhong.tw/sitemap.xml`. Nothing is
  disallowed: the page renders from `/api/status`, and crawlers have to fetch linked URLs to see
  their noindex.
- `/sitemap.xml`: exactly one URL, `https://status.skyhong.tw/`.
- `X-Robots-Tag: noindex` on every path except `/`, including `/api/*`, token endpoints (401),
  `/metrics`, `/healthz`, `/readyz`, `/livez`, `/feed.xml`, `/badge.svg`, assets, and 404s.
- No new data is published; the public/private boundary of `/api/status` is unchanged.

**Tests.** `npm test`: 64/64 passing, including `seo.test.mjs`. GitHub Actions *Tests* run
39928567784 on `7ccf711` succeeded (Node 22 and 24, Python 3.12 agent suite). A local server smoke
test checked each route's status and headers. Locally, `agent/run_local_tests.py` fails at import
under Python 3.14 ("offline tests deny production data reads"). That is an existing local
environment issue that CI does not have; this change does not touch `agent/`.

**Deployment (2026-10-23 09:00 UTC).** `git pull --ff-only` in
`/home/ubuntu/apps/sky-status-dashboard` to `7ccf711`, then `docker compose up -d --build
status-dashboard` under `/tmp/observe-sites-build.lock`. New image
`sha256:1a4cca9d0416…`, container healthy. The previous image is kept as
`status-skyhong-tw:pre-seo-20261023` for rollback.

## n8n.skyhong.tw (not changed here)

**Defect.** GSC reports `https://n8n.skyhong.tw/` (crawled 2026-10-03) as "Page indexed without
content". Anonymous `/` and `/signin` return 200 with the n8n editor shell and no `X-Robots-Tag`
or meta robots. `/robots.txt` returns 200 `text/html` (the SPA fallback), not a robots file.

**Ownership.** Not part of this repository. Routing is defined only by Traefik labels in
`/home/ubuntu/apps/n8n-dokploy/docker-compose.yml` on skyhong.tw. That file is not under git,
there is no n8n file in `/etc/dokploy/traefik/dynamic/`, and the container is `n8n`
(`docker.n8n.io/n8nio/n8n:latest`). The same compose is also stored in Dokploy's database as a raw
`composeFile` (`register-dokploy.sql`, composeId `n8n_cmp_skyhong`), so a Dokploy redeploy would
restore the stored copy.

**Proposed fix (for n8n's owner to apply).** Add a header-only middleware to the HTTPS router. It
does not alter n8n's authentication, workflows, or webhooks; it only adds a response header:

```yaml
      - traefik.http.middlewares.n8n-noindex.headers.customresponseheaders.X-Robots-Tag=noindex, nofollow
      - traefik.http.routers.n8n.middlewares=n8n-noindex
```

Apply it in both copies (the on-disk compose and Dokploy's stored compose), then run
`docker compose up -d --pull never n8n` in `/home/ubuntu/apps/n8n-dokploy`. This recreates the
container (a short n8n outage; `--pull never` avoids an unplanned `latest` upgrade). Check with
`curl -sI https://n8n.skyhong.tw/ | grep -i x-robots-tag`, and confirm that the status
dashboard's `n8n automations` monitor (`/healthz/readiness`) and the n8n scheduler heartbeat stay
green. Do not add a robots.txt `Disallow`, because Google has to recrawl the page to see the
noindex. Do not make workflows public to give the page content.
